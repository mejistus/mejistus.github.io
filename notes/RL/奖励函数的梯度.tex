\section{问题}

奖励 \(r(x)\) 对最终图像 \(x\) 的梯度 \(\nabla_x r(x)\) 一旦可得，奖励就能当成一个可微的“损失头”，梯度从最终图像直接反传到扩散模型参数。训练会更快，也更稳，所以很多工作喜欢这么设定。

\subsection{有奖励梯度 = 低方差、可直接优化}

如果 \(\nabla_x r(x)\) 可得，可以写成

\[
\max_\theta \;\mathbb{E}_{x \sim p_\theta}[r(x)] \quad \Rightarrow \quad \min_\theta \; \mathbb{E}[ -r(x)]
\]

因为 \(x\) 是由扩散采样链 \(x = g_\theta(\epsilon)\) 生成的（可微计算图），所以

\[
\nabla_\theta \mathbb{E} [r(g_\theta(\epsilon))] = \mathbb{E} \left[ \underbrace{\nabla_x r(x)}_{\text{reward梯度}} \cdot \underbrace{\nabla_\theta g_\theta(\epsilon)}_{\text{生成过程对参数的梯度}} \right]
\]

这叫路径导数（pathwise gradient）或重参数化梯度：不需要对随机采样分布做 REINFORCE 式的 \(\nabla_\theta \log p_\theta(x) \) 估计，方差通常更小，收敛也更快。

\hrule

\subsection{没有奖励梯度就得走“RL/score-function”路线，方差大、难稳定}

如果拿不到 \(\nabla_x r(x)\)，仍想优化 \(\mathbb{E}[r(x)]\)，典型就只能用：

\[
\nabla_\theta \mathbb{E}_{x \sim p_\theta}[r(x)] = \mathbb{E}[r(x)\nabla_\theta \log p_\theta(x)]
\]

这类估计（score-function / REINFORCE）在扩散里很难用。\(x\) 是一条很长随机链的结果，几十步到上百步，\(\log p_\theta(x)\) 的梯度噪声很大；reward 通常只在最终图像给一次信号，信用分配（credit assignment）极难；还要 baseline、value function、advantage 来降方差，value function 就是为这个服务的。

所以论文里常说 “high-variance Monte Carlo estimators”。

\hrule

\subsection{有奖励梯度可以做“终态反传”，实现极简、样本效率高}

“directly backpropagate gradient signals from the final state” 指的是：

\begin{enumerate}
  \item 采样得到最终图像 \(x_0\)
  \item 计算 reward（可微）\(r(x_0)\)
  \item 把 \(-r(x_0)\) 当 \(loss\)，沿着采样计算图（或某种可微近似）直接反传到 UNet/LoRA
\end{enumerate}

工程上省掉了 reward model 训练、value function，以及一整套复杂的 RL 算法结构。

\hrule

\subsection{但“奖励梯度可得”在现实里往往不成立}

人类偏好、人工打分、A/B 选择都不可微；外部评价器（黑盒 API、只返回分数不给梯度的审美模型）拿不到梯度；FID、带非光滑操作的 CLIP 变体、离散规则或安全策略可能不可微，梯度也不可靠；即便可微，模型也可能学会骗 reward 的梯度，而不是提升真实质量。

所以一些工作转向：只用 reward 标量 + KL 约束（你 SQDF 的 KL 项就是为了稳定），或者用 DPO/GRPO/偏好学习等。

\hrule

\subsection{和你 SQDF 这类方法的关系}

你现在的训练里，reward（审美）是通过 online\_loss\_fn(img) 得到的标量，然后你用

\[
\mathcal{L} = -\left(\gamma^{t}\, r(x) - \alpha\, KL\right)
\]

你并不依赖 \(\nabla_x r(x)\)，至少从训练逻辑上把 reward 当成标量权重；你用 KL 项把更新限制在“像 ref 的一步转移附近”，用 replay/buffer 提高数据利用率。

如果 reward 梯度真的可得，你还可以进一步把 reward 对 image 的梯度直接回传（更像“纯 differentiable objective”），但你就必须确保 reward 模块是可微且梯度可信。

\hrule

奖励梯度重要，是因为它把对偏好的优化从高方差 RL 变成低方差、可直接反传的端到端学习。但这个假设在真实 reward 场景里通常不成立，于是有了 SQDF、GRPO、DDPO 这类不依赖 reward 梯度的路线。

\section{\(\nabla_x r(x)\) 怎么求}

\(\underbrace{\nabla_x r(x)}_{\text{reward梯度}}\) 的求法取决于 reward \(r(x)\) 是否对输入 \(x\) 可微。

按三种最常见的情况说明，并给出 PyTorch 里的写法。

\hrule

\subsection{1) \(r(x)\) 是可微模型（最常见：CLIP/审美打分网络/RewardNet）}

假设 reward 是一个神经网络 \(r_\phi(x)\)，输入是图像张量 \(x\in\mathbb{R}^{B\times C\times H\times W}\)，输出标量（或每张图一个分数）。那 \(\nabla_x r(x)\) 就是对输入张量的反向梯度，用 autograd 直接拿：

\begin{lstlisting}[language=python]
# x: (B,C,H,W) float tensor, requires_grad=True
x = x.clone().detach().requires_grad_(True)

score = reward_model(x)          # (B,) or (B,1) or scalar
score_sum = score.sum()          # 变成标量方便求导

grad_x = torch.autograd.grad(
    outputs=score_sum,
    inputs=x,
    create_graph=False,          # 只需要一阶梯度通常 False
    retain_graph=False,
    only_inputs=True
)[0]                             # grad_x shape == x shape
\end{lstlisting}

几个容易卡住的地方：\(x\) 必须 requires\_grad\_(True)；算 score 时不要包 torch.no\_grad()，也不要对 \(x\) 做 .detach()；reward 模型内部如果有不可微操作（硬阈值、argmax、离散采样），梯度要么为 0，要么不稳定。

\hrule

\subsection{2) \(r(x)\) 是一个明确公式（可解析）}

比如你定义 reward 为某种可微的函数：

\begin{itemize}
  \item \(r(x)= -\|x-x^*\|_2^2\)
  \item \(r(x)=\text{mean}(\text{softplus}(x))\)
  \item 或一些可微的频域/梯度能量
\end{itemize}

那 \(\nabla_x r(x)\) 可以手推，也可以同样交给 autograd（推荐）：

\begin{lstlisting}[language=python]
x = x.requires_grad_(True)
r = -(x - x_target).pow(2).mean()
grad_x = torch.autograd.grad(r, x)[0]
\end{lstlisting}

\hrule

\subsection{3) \(r(x)\) 是黑盒/不可微（人类打分、API、规则指标、FID…）}

这时严格意义上 \(\nabla_x r(x)\) 不存在，或者拿不到。常见替代路线：

\subsubsection{(a) 有限差分近似（能用但非常贵）}

\[
\frac{\partial r}{\partial x_i}\approx \frac{r(x+\epsilon e_i)-r(x-\epsilon e_i)}{2\epsilon}
\]

维度太高（图像像素百万级）几乎不可行，除非做随机方向估计（SPSA/ES），但噪声大、样本开销巨大。

\subsubsection{(b) 训练一个可微 surrogate reward \(\hat r_\phi(x)\)}

用黑盒打分数据 \((x, r(x))\) 拟合一个网络 \(\hat r\)，然后用它的梯度当 \(\nabla_x r(x)\) 近似。

\subsubsection{(c) 不用 \(\nabla_x r(x)\)，改用 score-function/RL（REINFORCE/DDPO/GRPO/SQDF 类）}

也就是你现在这条路线：reward 只当标量信号，不要求对图像可微。

\hrule

\subsection{在 diffusion 里用上 \(\nabla_x r(x)\) 还要注意的一点}

要把梯度用到 UNet 参数 \(\theta\) 上，还需要链式法则：

\[
\nabla_\theta r(x_0)=\nabla_{x_0} r(x_0)\cdot \frac{\partial x_0}{\partial \theta}
\]

这要求保留从 \(\theta\) 到 \(x_0\) 的计算图：采样过程别 no\_grad，DDIM/ODE step 要可微。这在扩散里很吃显存，通常得少步数或截断反传，只反传最后几步；或者用 gradient checkpoint；或者像 SQDF 那样只做一步更新，避免全链反传。

\section{最大化奖励\(\nabla_\theta r(x_0)\)}

如果采样过程可以写成可微映射

\[
x_0 = g_\theta(\epsilon,\text{prompt})
\]

那么最大化期望奖励的“精确方向”，更准确地说是对 \(\mathbb{E}_\epsilon[r(g_\theta(\epsilon))]\) 的无偏梯度估计，可以用路径导数：

\[
\nabla_\theta r(x_0)=\nabla_{x_0} r(x_0)\,\cdot \frac{\partial x_0}{\partial \theta}
\]

实现里并不会显式算巨大的 Jacobian \(\frac{\partial x_0}{\partial\theta}\)，autograd 实际算的是 \(VJP := (\nabla_{x_0} r)\cdot J_{x_0}(\theta)\)。

难的是 \(\frac{\partial x_0}{\partial \theta}\) 在数学上存在、框架也能给，不等于工程上容易、梯度好用。卡点主要有这些。

\hrule

\subsection{采样是“长链展开”，反传代价爆炸（时间+显存）}

扩散采样是 T 次迭代（常见 20/50/100 步），每一步都跑一次（甚至两次）UNet。CFG 下每步要算 cond/uncond 两次 UNet，计算直接翻倍；反向传播还要保存每步的中间激活，或者 checkpoint 重新算。显存吃紧，速度也慢，比普通 LoRA 训练重很多。所以很多工作会截断反传，只反最后几步；或者做单步近似（SQDF 这种）；或者用 consistency model 缩短链。

\hrule

\subsection{采样里有随机性：你优化的是期望，但单条轨迹梯度噪声很大}

采样里常见形式：

\[
x_{t-1} = \mu_\theta(x_t,t) + \sigma_t\,\eta,\quad \eta\sim \mathcal{N}(0,I)
\]

这仍然可以重参数化（\(\eta\) 独立于 \(\theta\)），理论上可微。真正想优化的是 \(\nabla_\theta \mathbb{E}_\eta[r(x_0)]\)，但单次采样得到的梯度只是一个 Monte Carlo 估计，方差很大。想稳就要多采样、用控制变量或 replay buffer，算力需求又上去了。你现在的 buffer 和 PER，就是在缓解信号稀疏和方差大的问题。

\hrule

\subsection{“可微 ≠ 梯度好用”：容易出现梯度消失/爆炸/不稳定}

采样链里有很多会影响梯度质量的东西。scheduler 的一些操作（clamp/thresholding 等）可能让梯度在饱和区接近 0；VAE decode、图像归一化、reward 模型的归一化都会让尺度变得敏感；长链乘起来的 Jacobian 容易造成梯度爆炸或消失，类似 RNN 长序列反传的问题。结果就是，就算 autograd 能给 \(\partial x_0/\partial\theta\)，数值上也可能很难训练。

\hrule

\subsection{reward 梯度本身可能“不可靠”或“被钻空子”}

即便能拿到 \(\nabla_{x_0} r(x_0)\)，reward model 的梯度也可能指向投机取巧的方向（reward hacking）；模型被更新后分布迅速漂移，分布外的梯度会很乱；人类偏好、安全规则这类 reward 往往是黑盒或非光滑的，梯度本来就不存在。

所以很多方法宁愿用 KL 约束、偏好对比、分布约束等来稳住。

\hrule

\subsection{代码结构常常挡住 \(\partial x_0/\partial \theta\)}

实际代码里，rollout 经常包着 torch.no\_grad()，或者把中间 latents .detach() 存进 buffer。这样拿到的 \(x_0\) 不在计算图上，autograd 根本没法从 reward 反传回 UNet 参数。

要做“终态反传”，采样过程至少最后若干步得在 enable\_grad 下、且不 detach。这又回到第 1 点的显存和速度问题。

\hrule

\subsubsection{取舍}

\(\frac{\partial x_0}{\partial\theta} \) 在 PyTorch 里能算，难点不在求导本身：

\begin{enumerate}
  \item 长链反传成本极高。
  \item 单样本梯度方差大，要的是期望最优，不是某个噪声 realization。
  \item 梯度数值不稳定，来自 clamp、尺度和链式乘积。
  \item reward 梯度可能不可信，比如 hacking 或分布外。
  \item 实际代码经常为了省显存把图切断。
\end{enumerate}

折中的做法通常是只对最后 1 到 k 步开梯度，或者把 consistency model 当作可微软路解码器，这样既能用到 \(\nabla_{x_0} r(x_0)\)，又不至于爆显存。

\section{为什么不能直接使用雅可比？}

我们从来不显式构造那个巨大的 Jacobian。

\[
J_{x_0}(\theta)=\frac{\partial x_0}{\partial \theta}
\]

因为它的尺寸离谱：如果 \(x_0\) 有 \(D\) 个像素维度、\(\theta\) 有 \(P\) 个参数，那 Jacobian 是 \(D\times P\)。\(D\sim 10^5\!-\!10^6\)，\(P\sim 10^8\)，根本存不下也算不动。

但真正需要的是最终梯度 \(\nabla_\theta r(x_0)\)。

链式法则写成矩阵形式就是：

\[
\nabla_\theta r(x_0)=\underbrace{\left(\nabla_{x_0} r(x_0)\right)}_{1\times D}\;\underbrace{\frac{\partial x_0}{\partial \theta}}_{D\times P}
\]

这是一个\( 1\times P \)的向量（对每个参数的梯度）。

这里出现的乘法

\[
(\nabla_{x_0} r)\cdot J_{x_0}(\theta)
\]

就是 VJP（Vector–Jacobian Product，向量-雅可比乘积）。vector 指 \(v=\nabla_{x_0} r(x_0)\)，形状 \(D\)；Jacobian 指 \(J=\partial x_0/\partial\theta\)，形状 \(D\times P\)；product 得到 \(v^\top J\)，形状 P，也就是要的 \(\nabla_\theta r\)。

\subsection{为什么 autograd 说它在算 VJP？}

反向传播（reverse-mode autodiff）的核心能力，是给定输出的梯度（上游梯度），把它往前乘上每一层 Jacobian 的转置。整体效果等价于一次 VJP。

在 PyTorch 里，假设：

\begin{lstlisting}[language=python]
x0 = g_theta(...)          # x0: shape (D,)
r  = reward(x0)            # r: scalar
r.backward()
\end{lstlisting}

backward() 把标量梯度 \(dr/dr=1\) 作为起点，一路往回传。到达 \(x_0\) 这一层时，上游梯度就是 \(\nabla_{x_0} r\)，再继续往回乘上每一步的局部 Jacobian，最终得到 \(\nabla_\theta r\)。整个过程从未显式生成 \(J\)，但得到了 \(v^\top J\)。

\hrule

\subsection{一个不用扩散的小例子}

令 \(\theta\in\mathbb{R}^2\)，输出 \(x_0\in\mathbb{R}^3\)：

\[
x_0 = A\theta,\quad r(x_0)=\tfrac12\|x_0\|^2
\]

其中 A 是 \(3\times2\)。

Jacobian 是 \(\frac{\partial x_0}{\partial\theta}=A（3×2）\)，reward 对 \(x_0\) 的梯度是 \(\nabla_{x_0} r = x_0\)（3 维）。最终梯度

\[
\nabla_\theta r = (\nabla_{x_0} r)^\top A = x_0^\top A
\]

是一个 2 维向量。只需要算 \(x_0^\top A\)，不需要把 \(J\) 展开成一个大对象再做运算，现实里 \(A\) 巨大时更是如此。

\hrule

\subsection{VJP 与 JVP}

VJP 是 \(v^\top J\)，反向模式（backprop）擅长，适合标量输出、参数很多的情形，深度学习最常见。JVP 是 \(J u\)，正向模式擅长，适合输出很多、输入少，或做某些二阶和敏感度分析。训练网络一般都是标量 loss，所以几乎永远在做 VJP。

\hrule

\subsection{和你扩散训练的对应关系}

扩散里 \(x_0=g_\theta(\epsilon)\) 是一串迭代/网络调用的复合函数。你想要

\[
\nabla_\theta r(g_\theta(\epsilon))
\]

autograd 就是在沿着这串计算图做 VJP：把 \(\nabla_{x_0} r\) 作为“上游梯度”往回传，最后给你每个 UNet/LoRA 参数的梯度。

\hrule

扩散训练里，从 x\_0\_hat 到 vae.decode 再到 online\_loss\_fn 这条链上，哪一行开始产生上游梯度、哪一行被 no\_grad()/detach() 切断，决定了哪里能反传、哪里不能。
