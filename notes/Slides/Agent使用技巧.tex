\begin{frame}{Agent 能做什么、做不好什么}
  \begin{columns}[T]
    \begin{column}{0.5\textwidth}
      \textbf{\textcolor{video}{有参考就能做好}}\\[2pt]
      \begin{itemize}
        \item 读代码、顺着符号跳转、改代码、补测试
        \item 写样板/脚手架、格式化、翻译、写文档
        \item 跑命令、查日志、总结、做表、对比
      \end{itemize}
    \end{column}
    \begin{column}{0.5\textwidth}
      \textbf{\textcolor{hot}{没参考就做不好}}\\[2pt]
      \begin{itemize}
        \item 编参考文献
        \item 凭空实现领域特有的规则
        \item 替你做主观判断（这结果对不对、审稿人买不买账）
      \end{itemize}
    \end{column}
  \end{columns}
  \bigskip
  Agent 是\textbf{加速器}，不是\textbf{领域专家}。领域规则在你脑子里，不在它的训练数据里；
  这一整场要解决的，就是怎么把这些规则「外置」给它。
\end{frame}

\section{调研工作}

% 0:50
\begin{frame}{调研里 agent 能做什么}
  \begin{itemize}
    \item 给关键词/问题，抓 arXiv、搜论文、按主题分组、筛相关性。
    \item 精读单篇：提炼方法、贡献、关键数字、和别家的差异。
    \item 把多篇整理成对比表：方法 / 数据集 / 指标 / 结论。
    \item 生成综述段落、Related Work、给每篇写一句话摘要。
  \end{itemize}
  \medskip
  前提只有一个：\alert{给它读得到原文}。读不到，它就会编——下一张讲。
\end{frame}

% 0:50
\begin{frame}{调研最大的坑：文献幻觉}
  \begin{itemize}
    \item Agent 下载不了、访问不到某篇时，不会老实说「读不到」，
      而是被「给出答案」的奖励驱动，编一条像模像样的引用。
    \item 编出来的\alert{不容易察觉}：作者、年份、venue 都合风格，编号还顺。
    \item 应对：\textbf{自己先把 PDF 下载下来}，让它只读本地文件；
      读不到就明说，绝不凭印象。
  \end{itemize}
  \begin{center}
  \textcolor{soft}{\small 幻觉不来自它「傻」，来自它「够不到还要硬答」。给它真东西，它才不编。}
  \end{center}
\end{frame}

\section{修改实验}

% 0:50
\begin{frame}{自己维护一个领域 code base 仓库}
  \begin{itemize}
    \item 通用 agent 的训练数据里是「教科书式」实现；你的领域有一堆\textbf{不成文的规则}。
    \item 把这些规则沉淀成一个仓库：已验证的最小可运行代码、踩过的坑、约定的预处理。
    \item 让 agent 以它为\alert{参考}去改代码，而不是从零自由发挥。
  \end{itemize}
  \medskip
  \begin{center}
  \textcolor{soft}{\small 没有参考，模型给的代码从第一步就会错；有参考，它才有对的模板可抄。}
  \end{center}
\end{frame}

% 1:00
\begin{frame}{一个 AIGC 的例子：VAE 重建}
  \begin{center}
  \begin{tikzpicture}[>={Stealth[length=2mm]}, font=\footnotesize, node distance=4mm,
      box/.style={draw=#1, fill=#1!12, text=#1!75!black, rounded corners=2pt, minimum height=7mm, inner sep=4pt}]
    \node[box=soft] (img) {image};
    \node[box=accent, right=of img] (crop) {crop to 32x};
    \node[box=sig, right=of crop] (enc) {VAE encode};
    \node[box=sig, right=of enc] (dec) {VAE decode};
    \node[box=video, right=of dec] (png) {save PNG};
    \draw[thick, ->] (img) -- (crop);
    \draw[thick, ->] (crop) -- (enc);
    \draw[thick, ->] (enc) -- (dec);
    \draw[thick, ->] (dec) -- (png);
  \end{tikzpicture}
  \end{center}
  \begin{itemize}
    \item \textbf{crop 到长宽 32 的倍数}再做重建：长宽不整除会重建出黑图/黑边。
    \item \textbf{坚决不用 resize}：插值会改变伪影（artifacts），检测器对伪影敏感。
    \item \textbf{底层伪影用 PNG 保存}：JPEG 二次有损会再次引入/抹掉伪影。
  \end{itemize}
  这些规则不在任何教科书的默认里；没有参考，模型从预处理这第一步就写错，后面实验全白做。
\end{frame}

\begin{frame}{Agent 务必 Human in the loop}
  \begin{center}
  \begin{tikzpicture}[>={Stealth[length=2mm]}, font=\footnotesize, node distance=4mm,
      box/.style={draw=#1, fill=#1!12, text=#1!75!black, rounded corners=2pt, minimum height=7mm, inner sep=4pt}]
    \node[box=sig] (you) {you set the rule};
    \node[box=accent, right=of you] (agent) {agent step};
    \node[box=sig, right=of agent] (verify) {you verify};
    \node[box=video, right=of verify] (next) {next step};
    \node[box=hot, below=8mm of agent] (fix) {fix and retry};
    \draw[thick, ->] (you) -- (agent);
    \draw[thick, ->] (agent) -- (verify);
    \draw[thick, ->] (verify) -- (next);
    \draw[thick, ->, hot] (verify.south) to[out=270, in=0] node[right, font=\scriptsize] {not OK} (fix.east);
    \draw[thick, ->, hot] (fix.west) to[out=180, in=270] (agent.south);
  \end{tikzpicture}
  \end{center}
  \begin{itemize}
    \item 别让它一次跑完再一起看：错在第一步，后面全是错的。
    \item 每步都能验证：预处理对不对（看张图）、指标对不对、基线复现没。
    \item 小步 + 显式验收：改完跑什么、看什么、什么算过。你才是那个知道「这张图对不对」的人。
  \end{itemize}
\end{frame}

\section{工作区整理}

% 0:50
\begin{frame}{工作区：论文、代码、笔记各就各位}
  \begin{center}
  \footnotesize
  \begin{tabular}{lll}
    \toprule
    \textbf{资产} & \textbf{放哪} & \textbf{为什么} \\
    \midrule
    论文 & Zotero 统一管理，PDF 落本地 & 编号/标签/笔记可检索，agent 读得到 \\
    领域规则 & 自己的 code base 仓库 & 让 agent 照着改，而不是自由发挥 \\
    偏好/约定/坑 & 写成规则文件 & 交代一次，往后自动生效 \\
    \bottomrule
  \end{tabular}
  \end{center}
  \bigskip
  目的只有一个：把「在脑子里的」都\textbf{外置}成 agent 能读到的文件。
  你整理得越细，它越不需要猜，也就越少错。
\end{frame}

% 0:40
\begin{frame}{幻觉为什么产生——以及为什么「先下载」}
  \begin{itemize}
    \item 机制：agent 被训练成「给出答案」会得奖励；读不到某篇论文时，
      最像答案的行为就是\textbf{编一个}。
    \item 编造更难被察觉，因为它熟悉引用格式，能编出作者/年份/venue 都顺眼的条目。
    \item 所以「自己先把文献下载下来」不是省事，是\alert{切断编造的入口}：
      给它能读到的本地 PDF，它才不编。
  \end{itemize}
  \begin{center}
  \textcolor{soft}{\small 应对文献幻觉最有效的办法，是别让它「够不到」。}
  \end{center}
\end{frame}

\section{低成本实操}

% 0:50
\begin{frame}{低成本：opencode go plan + 开源模型}
  \begin{itemize}
    \item \textbf{opencode 的 go plan}：先出计划 → 你确认 → 再执行；省钱，也防跑偏。
    \item 开源模型性能很强、价格极低，\textbf{90\%+ 的活足够胜任}：
      读代码、改代码、写样板、总结、查日志。
    \item 贵的模型只留给最难的那 10\%：新算法设计、疑难 bug。
  \end{itemize}
  \medskip
  \begin{center}
  \textcolor{soft}{\small 安利：opencode 配开源模型，日常研究基本够用，还便宜。}
  \end{center}
\end{frame}

% 0:40
\begin{frame}{vibe-fork 你需要的一切插件}
  \begin{itemize}
    \item 缺什么工具，直接 fork 一个开源项目自己接，别等别人适配。
    \item 例：\texttt{llm-for-zotero} 原本不支持我的工作流，
      我 fork 了 \texttt{mejistus/llm-for-zotero}，加上了 opencode 支持。
    \item 思路：开源 + vibe 编码，一下午就能把常用工具接进你的 agent——
      Zotero 本地库 $\to$ llm-for-zotero $\to$ agent 只读本地 PDF（接回第 3 节）。
  \end{itemize}
\end{frame}

% 0:40
\begin{frame}{subagent 提高并行效率}
  \begin{columns}[T]
    \begin{column}{0.52\textwidth}
      \begin{itemize}
        \item 互不依赖的活拆开\alert{并行}：同时精读三篇、分头改三个模块、一边审一边写。
        \item 你只收结论，不收文件转储；串行的活不值得并行。
        \item 判断标准：两件事有没有先后依赖？没有，就并行。
      \end{itemize}
    \end{column}
    \begin{column}{0.48\textwidth}
      \begin{center}

\begin{frame}{设置 goal，但别任务漂移}
  \begin{center}
  \begin{tikzpicture}[>={Stealth[length=2mm]}, font=\footnotesize, node distance=4mm,
      box/.style={draw=#1, fill=#1!12, text=#1!75!black, rounded corners=2pt, minimum height=7mm, inner sep=4pt}]
    \node[box=sig] (g) {goal};
    \node[box=soft, right=of g] (s1) {step 1};
    \node[box=soft, right=of s1] (s2) {step 2};
    \node[box=soft, right=of s2] (s3) {step 3};
    \node[box=video, right=of s3] (done) {done state};
    \draw[thick, ->] (g) -- (s1);
    \draw[thick, ->] (s1) -- (s2);
    \draw[thick, ->] (s2) -- (s3);
    \draw[thick, ->] (s3) -- (done);
  \end{tikzpicture}
  \end{center}
  漂移来自：goal 太大 + 没有「完成」的定义，agent 越做越偏还停不下来。两条对策：
  \begin{itemize}
    \item \textbf{拆解过程}：把大 goal 拆成带顺序的小步，每步一个产物。
    \item \textbf{显式定义完成}：做完是什么样、跑什么、别动什么——没定义完成，
      它就把「看起来做完了」当完成。每完成一步，回到 goal 检查一次：还在不在原路上。
  \end{itemize}
\end{frame}

\begin{frame}{一张检查清单}
  \begin{center}
  \footnotesize
  \begin{tabular}{ll}
    \toprule
    \textbf{开工前} & \textbf{过程中 / 收尾} \\
    \midrule
    领域规则落到 code base 了吗？ & 每步可验证吗？ \\
    PDF 在本地吗？ & human in the loop 了吗？ \\
    goal 拆了吗？ & 能并行的并行了吗？ \\
    「完成」定义了吗？ & 读 diff、跑测试了吗？ \\
    & 每条引用都能在本地 PDF 找到吗？ \\
    \bottomrule
  \end{tabular}
  \end{center}
  \bigskip
  \begin{center}
  \textbf{一句话：} 把领域规则外置、把 PDF 落本地、把每一步变可验证，
  agent 才会从「会聊天的玩具」变成「能交付的帮手」。
  \end{center}
\end{frame}
