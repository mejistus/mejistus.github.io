hatex

LaTeX articles, rendered in the browser.

One script turns a .tex file into a web page: numbered equations, booktabs tables, figures and subfigures, TikZ, theorems and proofs, algorithms, citations and clickable cross-references. No TeX installation and no build step. Unknown commands degrade to their text instead of failing.

Quick start

Load KaTeX (for the maths) and hatex, then render a source into an element:

<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/katex@0.16.9/dist/katex.min.css">
<script src="https://cdn.jsdelivr.net/npm/katex@0.16.9/dist/katex.min.js"></script>
<link rel="stylesheet" href="https://mejistus.github.io/hatex/lib/hatex.css">
<script src="https://mejistus.github.io/hatex/lib/hatex.js"></script>

<article id="paper"></article>
<script>
  fetch('paper.tex')
    .then(r => r.text())
    .then(tex => HaTeX.render('#paper', tex));
</script>

The source can be a whole document (\documentclass … \begin{document}) or just its body. The preamble is read for \newcommand, \definecolor, \newtheorem and \usetikzlibrary. Serve the page over HTTP, not file://, so the .tex file and TikZ SVGs can be fetched. For highlighted code, add Prism and its language components; don't add a Prism theme.

API

CallWhat it does
HaTeX.render(el, source, options)Parses source into el (an element or a selector) and wires up TikZ, links, table fitting, copy buttons and zoom.
HaTeX.parse(source)Returns the HTML string. It needs no DOM, so it also runs in Node for static sites.
HaTeX.enhance(el, options)Does the wiring for HTML that was rendered earlier, for example by parse at build time.
HaTeX.lint(source)Returns problems as [{ line, severity, message }]: unclosed environments, unbalanced braces or $, unknown labels and citations, duplicate labels, wrong cell counts.
HaTeX.tikzSvgs(el)Returns the pictures compiled in this session as { file, svg }, ready to save for pre-rendering.
HaTeX.BibBibTeX parse and format (to \bibitem), and lookup of a DOI or arXiv id.

Options for render and enhance:

OptionDefault

tikzLivetrueCompile pictures that have no SVG in the browser.

TikZ

Pictures are compiled by real TeX running in WebAssembly (TikZJax). That is about 6 MB and a few seconds per picture the first time, so for readers you compile once and ship SVGs:

  1. Render your page with tikzSvgBase: null and let the pictures compile.
  2. Save each { file, svg } from HaTeX.tikzSvgs(el) into your tikz/ folder.
  3. Deploy. Each picture now loads from tikz/<hash>.svg. The hash covers the picture's code, so editing a picture falls back to compiling it until you save it again.

Labels inside a picture must be ASCII (plain TeX has no CJK fonts); maths in labels is fine. Any nn* style (nnconv, nnpool, nnattn, nnflow, nnskip, …) pulls in a set of definitions for neural-network diagrams.

Theming

Output is scoped to .hatex and coloured with CSS variables, so a page restyles it without touching the rules:

.hatex {
  --hx-ink: #000;         /* headings, tables, rules */
  --hx-muted: #222;       /* paragraphs, captions */
  --hx-accent: #0b57d0;   /* links, section numbers, inline code */
  --hx-font-heading: Georgia, serif;
}

Put data-theme="dark" on the element or any ancestor for the dark palette, or data-theme="auto" to follow the system. In dark mode, author colours are lifted so they stay readable, and TikZ keeps a light sheet to draw on. The plain style in the playground above is just a handful of these variables.

Node and static sites

parse needs no DOM, so you can render at build time and ship plain HTML. Use the ES module build, hatex.mjs:

import katex from 'katex';
import HaTeX from './hatex.mjs';

HaTeX.use({ katex });
const html = HaTeX.parse(source);   // → <article class="hatex">${html}</article>

Limitations

  • It is not a TeX engine. It covers the subset articles use, and has no page layout: \vspace, \newpage and float placement are ignored.
  • \title, \author and \maketitle produce nothing, so put the title block in your HTML.
  • Maths is whatever KaTeX supports; siunitx and similar packages are not available.
  • One file per document: no \input or .bib files. Write thebibliography instead (HaTeX.Bib can generate the entries).
  • The output is meant for your own writing. Sanitise it before rendering sources from other people.
